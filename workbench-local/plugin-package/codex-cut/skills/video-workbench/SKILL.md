# Codex Cut 视频制作

Codex 负责内容理解、创作和执行；用户在本地工作台查看、调节与确认。沿用现有工作台、剪辑引擎和组件，不新建内置 AI 或另一套编辑器。

## 接手工程

1. 用 `workbench_status` 检查配置；需使用时用 `open_workbench` 启动/复用，再将返回 URL 用 Codex 的浏览器面板打开。
2. 用 `read_project` 的 summary 读取当前素材、修订、选择、草稿、段落、反馈和确认。当前工程非空时，不能因为用户给了另一条视频就静默覆盖；先保存/隔离当前工程，再在用户指定范围内切换。
3. 修改前读取该段 production 和必要的 cut 文稿。存在未保存修改时先保留用户草稿。遵守配置工程及其上层 AGENTS.md；不得从旧对话猜当前状态。

## 制作方法

整片制作采用六步：**粗剪 → 划分视觉段落 → 决定视觉对象 → 决定视觉布局 → 决定包装对象 → 调用组件完成包装**。

- 粗剪删除失败口、重复和无意义停顿；检查句意与音频切点，交带原声粗剪给用户确认。转写正确不等于剪干净。
- 先读全片，按表达目的划段。明确每段观众要理解什么、主视觉是什么、辅助对象是什么。人物、真实素材、文字、数字、录屏、图解均可成为主视觉。
- 对象必须有真实内容、关系、位置和出现顺序。一段内部可以连续演变；不能把设计说明直接变成画面字幕。三张卡片就实现三张有内容的卡片，不能用一行说明冒充。
- 先设计整片再选组件。检查连续段落的构图和视觉密度；不能把全片默认套成“人物左、文字右”，也不能为变化而变化。优先使用用户认可的视觉语言，布局仍按当前内容设计。
- 先按表达职责查新视觉资产库的组件、特效或 recipe，再选择明确版本；需要时原创或从参考提炼。旧 194 组件库已退役，仅供历史项目兼容，不用于新选型，也不恢复旧研究目录。不把 DJI 专用分镜变成通用模板，不以多加几个固定模块替代新库的制作与复用链路。
- 将出现、强调、移动、消失绑定稳定词 ID，由当前粗剪映射到帧；区分源时间、全片时间和段落局部时间。
- 缺真实素材时挂到对应段落，说明表达目的和出现位置；用户可补充、接受明确替代或先做其他段。示意必须明确，不能虚构录屏、测试结果或事实。

## 参考、资产与风格包

按任务需要读 [实现与操作](references/operations.md) 的新库接口。`read_project` 的 `visual-library` 包括候选与可用版本；`visual-asset`、`style-pack` 用 `{id,version}` 读固定版本；`references` 看真实参考进展。旧 `library` 只是新库 ready 资源的兼容入口，`component` 只读历史组件。

- 参考流程区分：导入与准备 → 实际观察记录 → 独立重建候选 → 原效果渲染检查 → 换当前内容验证 → 用户明确选定可用。抽帧和转写只帮助定位，不能替代对目标片段完整运动、前后衔接及有关声音的检查。
- 无视觉能力时可做素材准备、结构分析或候选实现，但不得填写 `visualInspected:true`、记录未实际看过的视觉检查或声称视觉通过；未听声音同样不能填 `audioInspected:true`。报告缺少的证据与仍待完成的门。
- 重建的是表达机制、布局和运动逻辑；参考品牌、原片画面、水印或整个截图不能作为“组件”直接复用。资产必须能替换真实内容与媒体、调参数、绑定语义事件，并在合法时长内确定性播放。黑框、假恢复或只写设计说明均不算实现。
- 控件支持 text/number/color/boolean/select/list；用 contentParameters 明确内容控件，previewBackground 声明预览底色；主视频需求 requiresSourceMedia、补充素材槽、语义 cue 和时长范围要明确声明。素材库样片用 materialSceneId 读取目标段落实际绑定，不能伪造 provided。新资产版本不可覆盖旧版本。候选可用 `trial:true` 加到隔离目标段落试用，不会自动成为可用资产。
- 资产样片为静音技术样片。原效果使用参考区间；换内容使用当前连续粗剪并从第 0 帧开始，不能继续以原参考素材冒充复用。比较真实输出与替换内容，不能只改颜色、时长或 cue 就声称换内容验证完成。
- Codex 对实际样片的 `visual`/`reuse` 检查是证据记录；普通自评、测试通过、渲染成功都不是用户认可。插件不提供 ready 写入口；用户在工作台明确选定资产或风格包，后端核验所需证据。不得通过其他操作传 `userConfirmed` 或伪造 `accepted`。
- 风格包固定引用本机资产版本，声明覆盖范围、文字/运动/构图/声音规则、token 与适用限制。包内独立样片不等于整包连续演示；只有实际生成并看过连续演示后才报告该项完成。当前风格包是本机版本集合，不是已实现可跨机器安装的包文件。

新库默认为空；五项原创几何示例仅在明确需要时运行配置工程的 `node examples/paper-style/import.mjs` 导入候选。新 SCENE 支持现有动画保存与目标 cue/媒体重绑定；包含新库 OBJECT 的嵌套 .cutanimation 暂时拒绝保存/打包。恢复应配对代码、项目与项目内 visual-library，不把风格包称为独立可安装文件。

库操作使用刚读取的库 revision，cut 和 production 各用自己的 revision。库写入不覆盖工作台本地参数草稿；制作操作发现未保存草稿必须先保护，不能借库操作绕过用户锁。

## 制作与审阅循环

整片分镜确认后，逐段实现与带原声渲染。局部返修直接处理受影响段落，不机械重跑全部设计步骤。

1. `update_project` 提交已读取版本上的设计/参数修改。复杂画面代码在配置工程中制作，按需读 [实现与操作](references/operations.md)。用户覆盖参数与锁定字段不能被重写。
2. `render_segment` 只生成指定段落，轮询 `read_project` 查看完成状态。检查实际画面和同步，再交用户审阅；没有听过音频就不声称听过。
3. 只有用户明确认可这段具体视频版本后才能 `approve_segment`。认可分镜、同意开始、测试成功或模型自评都不是成片确认。已有明确认可无需反复问。
4. 全部当前段落确认后 `assemble_video` 复用已确认画面和完整粗剪音轨。最后审阅整片衔接、节奏和音画，再交付。

修改已确认段落时保留旧结果；不得为了让按钮可用而伪造确认、清空反馈或改指纹。共享动画代码、粗剪或时间范围变化可能使多段失效，要报告实际影响。
