# Codex Cut 视频制作

Codex 负责内容理解、导演判断、具体造型、动画实现和实际检查。工作台负责项目、预览、编辑、版本和渲染；用户决定最终审美。组件可复用、改造或原创，直接使用现有 Remotion 能力，不把库当作创作边界。

## 接手当前任务

1. 用 `workbench_status`、`read_project` 的 summary 核对实际 projectDir/contentId、当前声音、修订、未保存修改和反馈。需要服务时用 `open_workbench` 启动或复用。不得从旧聊天猜当前状态；新内容建立独立工程，当前非空工程不能静默覆盖。
2. 读取项目最新采用稿、已有用户决定、当前 AGENTS 及本次交付目标。已有声音、锁、参数覆盖和验收都按具体版本保留；旧片不因公共默认改变而重做。
3. Dots 新工程的唯一制作入口是源码仓库 `tools/dots-production/WORKFLOW.md`；共用色彩字体和运动语言，按本期内容设计具体物件与整体布局。现有 authoring schema 1 工程继续按 `legacy/NATIVE_AUTHORING_V1.md`，不自动迁移在途影片。服务 `productionAuthoringGateVersion:2` 同时支持新旧版本，读取 `authoring.workflow/nextAction` 判断当前流程。
4. 其他方向依用户选择及工作区方法，不因插件包含 Dots 就强制改风格。真人素材、非真人讲解与混合形式使用所属主线；个人配音不等于真人出镜。

## 从真实内容形成实际画面

保留六步创作判断：粗剪、视觉段落、视觉对象、视觉布局、包装设计、动画实现。它们可往返，不是六道审批；需要粗剪时按实际录音删除失败口与重复，不能用转写正确代替剪辑听审。

全片先简排理解任务、主体分布、信息密度与前后关系，然后为本期不同难点做代表样片。实际材料、具体物件和内部变化先在代表片段验证，再扩展。只完成开头不能证明案例、产品和抽象机制都成立。用相邻及同类真实画面对照，最后连续看整片。

非真人内容涉及真实人物、公司、机器、产品、事件和资料，分镜定稿前主动检索并核对相关原图、影像、界面与原始资料。准确、可用、可看清时优先采用；素材承担对应内容的证明和观看主体，不只缩成角落的来源。抽象内容可以图解，不硬配无关实拍。完整规则在源码 `workbench-local/methods/FACELESS.md`。

设计从具体物件、可见依据和内部事件出发；不能把文案先压成概念词、框和箭头，再补装饰。已采用的研究通过 `tools/dots-production/studio/CRAFT.md` 的代码和真实实例进入制作：框的组合、粗重文字块面、内外边界、细部、执行和反馈、注意力交接。不同任务需要不同安排，固定页眉、三张卡或共同进场效果不能成为全片默认结构。

原生 design/beats/program、词锚点及场景代码是实现依据。复杂状态机可按需使用，Dots 新流程不重复维护全片动作脚本与 words 副本。字段完整和代码能渲染不代表画面精致。主要动作绑定稳定词 ID，分清源时间、全片时间与局部时间，不重复加入已解析偏移。

## 实现、观察与验收

按当前工程的 `workbench-local/SCENE_MODULES.md` 实现可编辑参数与语义 cue。React/SVG、Canvas、着色器和已支持的 Three.js 都可用；先查真实 runtime 能力，不安装另一套编辑器绕开现有工程。用户覆盖及锁继续高于共同默认值。

1. 通过 `update_project` 修改当前版本；有未保存编辑先保留。段落代码、参数和实际素材依赖共同纳入渲染身份。
2. `render_segment` 生成当前段落。代表样片先实际看完整运动、声音及目标观看尺寸，再比较对应参考。`studio capture` 从原生渲染生成证据和空白观察，不生成通过结论。技术验证、作者观察、用户认可分别报告；缺视觉或听辨能力时如实保留未完成，不能填假观察。
3. 记录具体可见差距并返修；不能以素材清单、方案文字、视频解码或像素变化推断已达到风格。修正后只复查受影响部分，不为微调重跑全套工程检查。
4. `production/storyboard` 从已有渲染抽帧，用于相邻、同类和整片统筹；静帧不替代动态。`production/visual-review` 及当前制作观察绑定实际 scene/key/renderId；旧版本记录只作历史。
5. 只有用户明确认可具体视频版本后 `approve_segment`；认可分镜、允许开工、自评通过均不算。已有明确授权不反复索取。所有当前段落认可后 `assemble_video`，实际回看整片衔接、节奏和混音后交付。

旁白、BGM和音效按工作区共同声音配置及本期接受记录。需要音乐时由 Codex 制作含口播、等长且对齐当前粗剪的完整混音，通过 `production/soundtrack` 绑定；不把场景中播放声音假设为正式音轨。混音改变使相关认可失效，须如实处理，不能改指纹或清空反馈绕过。

## 研究、资产和恢复按需读取

- 仅研究或拆解：读源码 `tools/reference-study/README.md`，保留文案与画面、具体元素、动作、时间码和实际依据，不自动制作影片。制作新片只按难点回查已整理实例，不重新全量研究。
- 原创/复用资产或风格包：读 [操作协议](references/operations.md)。固定 id/version，先原效果再换实际内容验证；候选、实际观察与用户选定分开。原片品牌、水印或截图不能冒充可换内容的组件。默认资源库为空，旧库仅兼容历史，不把资产入库当成每次原创的前置门。
- 可视化编辑、锁和恢复：同一操作协议及源码场景协议。内容与样式参数按真实覆盖关系处理；重要节点使用配对 checkpoint，代码与工程一起恢复到副本。只恢复 JSON 不声称回退了动画代码。
- 安装、运行状态与原生接口：读 [操作协议](references/operations.md)。插件文件更新不代表运行服务或旧会话指令已自动刷新；忙碌服务不得强行重启。

实际视觉判断由主代理负责，技术检查只提供证据。不增加用户表单，不把自动评分或子代理结论当作用户接受。
