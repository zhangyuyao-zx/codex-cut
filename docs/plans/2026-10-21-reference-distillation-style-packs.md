# Codex Cut 对标视频提炼与整片风格包升级计划

日期：2026-10-21。状态：计划已整理，功能尚未实施。当前代码基线为独立工作台 v0.1.0，提交 `a40c566e740feb53b5868d22821e72d570b9075b`。

本计划承接本轮已确定的新方向：旧 194 项退出新库，后续从用户提供的对标视频中提炼可用的组件、特效、包装方案与风格，制作、验证并经用户选定后入库。整片风格包作为可整套选用的方案。原计划中的旧组件扩充、194 项逐项全面验收，不再作为后续开发目标。

第一轮的完成标准是：一条真实对标视频产生可编辑资产和一套可用风格包，再用一份不同的真实内容完成包装、修改、保存重开、逐段确认和合成。只有目录、拆解文字或原片上的仿制样片，都不算完成这一闭环。

## 1. 产品目标和工作方式

用户在 Codex 中提供参考、讨论取舍和提出修改；Codex 理解视频、做视觉判断并实现动画；工作台提供实际预览、参数编辑、来源记录、资产管理、版本保护与视频制作。继续使用本地工作台和现有剪辑、时间映射、Remotion 渲染能力。

“蒸馏”在本次升级中指分析成片的可观察表现、重新实现和沉淀可复用资产。它不表示已经获得原作者工程、源码或唯一的制作方法，也不涉及训练新模型。

两条流程共用资产库，但不互相覆盖工程：

```text
建库：对标视频 → 画面和声音分析 → 候选资产与风格方案 → 代码重建
     → 换内容验证 → 用户选定 → 可用资产和风格包

制作：用户素材 → 粗剪 → 视觉段落 → 对象、布局和包装设计
     → 按内容选用风格包中的资产或原创 → 逐段原声样片
     → 用户确认 → 合成与整片审阅
```

制作仍执行六步方法，先设计当前视频，再选实现。选了风格包，也要重新决定重点、证据、主副视觉、构图和出现顺序；缺少合适资产时可以原创，不能强迫内容适配已有版式。

## 2. 旧成果如何处理

| 现有部分 | 升级处理 |
|---|---|
| 旧 194 项及其预设、收藏 | 退出新库选用与推荐；停止扩充、统一外观和逐项全面验收 |
| 旧工程实际引用的组件和样片专用动画 | 保留隔离的历史兼容入口及固定版本，维持旧工程可查看、可恢复；不混入新库数量和默认列表 |
| 无引用的旧组件实现 | 核对引用并保存可恢复快照后，从活动目录移出；不以隐藏旧目录冒充完成退役 |
| 剪辑、素材、转写、词级时间映射、原声处理 | 继续使用 |
| 对象参数、用户覆盖与锁、修订和撤销 | 继续使用，并接入风格包 |
| 动画保存、素材替换、口播重绑定、动画包 | 作为新资产制作和复用的基础，按所需能力扩展 |
| 逐段渲染、反馈、确认、合成和工程备份 | 继续使用 |

第一阶段先冻结历史版本、统计实际引用，再关闭旧库的新选用入口。历史兼容依赖收在明确位置，避免新内容继续依赖旧 194 项。清理不删除原始视频、用户工程、已确认视频或唯一恢复副本。

## 3. 新资产库的两层结构

### 单项资产

| 类型 | 保存的能力 | 典型例子 |
|---|---|---|
| 组件 | 一个独立、可编辑的视觉对象 | 数字、标题、图形标注、图片容器 |
| 特效 | 可施加给对象或相邻场景的运动与呈现方式 | 逐项出现、遮罩揭示、路径绘制、焦点切换、转场 |
| 包装方案 | 一段表达的对象关系、布局、动作顺序与素材入口 | 数字实证、流程说明、前后对比、截图讲解 |

不按每个颜色和字体组合生成一个新组件。相同功能优先保存为参数或变体；不同表达任务才形成独立包装方案。旧样片的固定词号、文案和素材路径不能成为新资产的隐含输入。

每项资产保存：稳定 ID、版本、类型、用途、来源片段、实现代码、参数、可编辑对象、素材槽、触发事件、支持画幅与时长、依赖、预览和验收状态。文字、数字、图片、列表数量等结构性输入按实际需要开放，不能仅暴露颜色和缩放。

特效和包装方案的描述分别说明作用对象、起态、运动过程、终态和使用条件。不能把包含整块背景的场景直接当作所有对象的默认叠加效果。

### 整片风格包

风格包是固定版本的配套资产、视觉规范和编排方式的集合。

| 组成 | 内容 |
|---|---|
| 视觉规范 | 字体层级、配色、留白、间距、圆角、线条、背景和装饰方式 |
| 配套资产 | 组件、特效、包装方案及其明确版本、默认参数 |
| 动效规范 | 进入、强调、退出、错峰、焦点移动和场景衔接的默认方式与时间范围 |
| 声音使用方式 | 有参考时记录提示音、强调音和音乐节奏的作用位置；实际音频使用独立可替换素材，保留目标视频原声 |
| 编排指导 | 哪类内容适合人物、数字、流程、图解或留白；如何调节信息密度与阅读节奏 |
| 适用范围 | 题材、支持的画幅、素材条件、已覆盖的表达任务与尚缺能力 |
| 风格演示 | 同一风格下不同表达方式组成的连续样片 |

整片编排指导由 Codex 结合内容执行；程序检查参数、素材、时间和兼容性。不能靠一套固定段落顺序让所有视频看起来一样。

风格包可以逐步补充，不要求第一条参考就覆盖所有表达任务。缺少的能力显示清楚，不自动从旧库填充。

## 4. 对标视频的提炼流程

### 接收和留存

参考视频进入独立参考工程，保存文件身份、时长、帧率、音轨、来源和用户要求。参考视频不走覆盖当前制作工程的导入路径。链接只有在内容实际可读取时才能继续分析；不能用网页标题代替视频内容。

### 分析和候选提取

分析所选范围的完整画面和声音，记录视觉段落、屏幕文字、对象关系、构图变化、进入/强调/退出、口播或音乐触发、素材需求和风格规律。运动判断结合连续播放与关键状态，不只看稀疏静帧。

每个候选关联原片时间区间及关键状态，并说明可复用的部分、必须替换的内容、实现依赖和未确定事项。相似效果去重，同一风格的细微差异优先形成变体。

有视觉能力的 Codex 检查真实视频与帧；无视觉能力的执行方可以准备媒体、转写和结构资料，但不能把文字推测标为视觉提炼完成。视觉判断由有相应能力的执行方或用户补齐。

### 代码重建和参数化

Codex 根据实际观察重新实现可程序化的画面。参数包含需要替换的内容、素材和样式；对象与动作有明确身份和对应关系。复杂三维、实拍、特殊纹理和音效等记录为资产依赖，按需另行制作或提供，不承诺从成片恢复这些原始文件。

原片时间仅作为分析证据。可复用动作使用语义事件，例如“总量出现”“第二步展开”“瓶颈强调”；制作时将事件绑定目标文稿的真实词 ID。固定时长动作保留帧数规则，跨段转场使用相邻场景的实际画面。

### 对照和换内容验证

先对照原片检查主要构图、对象关系与运动，再换一份不同的文案、素材和口播节奏。适用时验证长短文字、不同列表数量、不同数字位数、素材比例和时长变化。

检查内容准确、阅读时间、遮挡和溢出、动作同步、素材替换、参数修改、保存重开与输出一致性。遇到超出支持范围的内容，提示改布局、改方案或补素材，不能静默裁掉信息或无限压缩动画。

### 用户选定和入库

用户集中观看候选效果并决定保留哪些。分析和制作过程中不增加逐项强制确认关卡；只有真实取舍、缺失输入和用户最终选择需要交互。

候选状态和可用状态分开。程序检查、实际渲染、视觉检查和用户选定分别记录；没有真实参考时只能完成基础能力与夹具验证，不能伪造参考提炼结果。

资产入库认可只表示可以复用该资产，不替代未来每条影片的段落确认。

## 5. 风格包如何应用到整片

1. 选择风格包并观看连续演示，读取覆盖任务与素材条件。
2. Codex 完成当前视频的视觉设计，为不同段落选合适的包装方案；允许原片人物、单项资产组合和原创画面。
3. 解析共享样式、段落参数和用户覆盖值，绑定目标口播及素材，生成可审阅候选。
4. 逐段修改、原声渲染和确认，最终合成并检查衔接。

参数优先级：风格包默认值 → 段落已保存的显式设置 → 用户覆盖值。锁定字段继续限制 Codex 写入。换风格前列出实际冲突和影响范围；不绕过锁，也不直接覆盖用户调整。

项目固定风格包、资产和实现版本。库中更新发布新版本，不自动改已有项目；用户选择升级后再生成候选。项目保存解析后的样式与依赖摘要，预览和导出使用同一份结果。失败保留上一可用结果，旧任务不能覆盖新修订。

## 6. 工作台界面

顶部保留“剪辑”“包装与审阅”，将“组件”改为“视觉资产库”。对话继续在 Codex。

资产库提供三个入口：

- 风格包：连续样片、配套资产、适用内容、选择使用。
- 单项资产：按表达用途搜索组件、特效和包装方案，查看效果与可编辑参数。
- 对标与提炼：参考视频、时间定位、候选列表、制作进度与待审阅结果。

左侧负责筛选与选择；中间保留等比完整预览，可切换参考片段、重建结果和换内容结果；右侧显示参数、素材槽、包组成或应用设置。来源与高级实现信息折叠。

风格包封面和连续样片要体现多种构图。卡片、文字和动效预览采用可辨认的显示尺度，尚无预览的候选明确标记，不用无内容黑框冒充效果。

制作页显示当前包及版本，单段支持局部调整。普通参数编辑即时预览，不重新调用模型或重渲染整片。

## 7. 工程改造范围

| 模块 | 改造内容 |
|---|---|
| 动态资产目录 | 替换新库对旧 `COMPONENT_LIBRARY` 的固定绑定；支持版本、状态、检索、收藏和历史兼容解析 |
| 场景与参数协议 | 在现有模块能力上增加所需的列表、选择项和素材描述，提供可复用事件与显式能力约束 |
| 风格包服务 | 保存包定义、固定成员版本、共享样式、使用指导、覆盖范围和项目选择；解析为现有可渲染场景输入 |
| 参考工程 | 独立保存来源、分析证据、候选与制作阶段；支持进度、恢复和失败重试，不另建一套内置模型对话 |
| 动画与媒体复用 | 延用保存动画、重新绑定、素材替换和现有打包校验；补齐新资产的参数与依赖记录 |
| 预览与制作 | 同一实现和参数驱动预览/输出，沿用局部渲染、反馈、用户确认和合成 |
| 插件与 Skill | 更新现有 Codex Cut 入口，区分建库与制作；通过现有桥接方式提供参考、候选、资产和风格包操作 |
| 备份与文档 | 新资产、包版本和项目选择纳入匹配快照；更新旧组件目标、安装入口和已知边界 |

当前注册表还固定在 194 项，收藏上限也写死为 194；需要替换实际目录和校验依赖，不能只改页面名称。现有场景参数主要为文字、数字、颜色和布尔值；新增内容结构要同时接通面板、校验、保存与渲染。

新的参考视频、证据、候选和用户资产默认放在独立本地目录，建议使用忽略目录 `projects/visual-library/`，由服务提供受限访问。引擎和协议代码纳入 Git；参考原片、私人文稿与渲染不自动进入公开仓库。公开示例仅使用明确可公开的素材。

目录和缩略图按需加载，不同时为全库启动播放器。媒体处理沿用后台任务和流式文件处理；一次提炼按阶段保存结果，避免分析、编译或渲染长期阻塞浏览器交互。

首轮风格包先实现工作台内的组合、版本和使用闭环。独立可分发风格包文件及跨机器安装作为后续范围；现有 `.cutanimation` 功能继续可用，不能把逻辑风格包描述为已完成的独立安装包。

## 8. 实施阶段和验收

| 阶段 | 交付 | 验收条件 |
|---|---|---|
| U0 基线与退役准备 | 配对快照、旧引用清单、旧库退出方案、两处已知问题的修复 | 旧工程数据和确认不丢；预览为空时页面仍可操作；专用原模块误用会提前报缺失触发点，正常保存/重绑定路径可用 |
| U1 新资产库基础 | 动态目录、单项资产协议与界面、历史兼容入口 | 真实新资产能注册、检索、预览、调参、保存重开；新库没有旧 194 项和伪造的可用候选 |
| U2 对标提炼闭环 | 独立参考工程、时间证据、候选、代码重建和换内容对照 | 首条真实参考中一组代表性候选完成重建，换内容后可编辑、可播放和可导出；阶段记录可恢复 |
| U3 整片风格包 | 包定义、成员版本、连续演示、项目选择及单段覆盖 | 同一包支持不同表达画面；整片风格一致；参数、素材和口播可替换；锁与手动调整保留 |
| U4 新内容实际制作 | 使用风格包完成一条不同内容的视频，逐段反馈、确认与合成 | 真实原声同步、段落衔接和整片审阅通过；用户认可的资产及视频版本分别记录；修一段不意外改其他段 |
| U5 定版与同步 | 版本、插件、文档、备份范围与 GitHub 同步 | 新任务能使用更新插件；关闭重开可继续；代码、状态和实际能力一致，公开仓库不含私人素材 |

阶段按上述顺序推进。工程基础可在没有参考视频时进行；U2 的真实提炼需要首条可读取的对标，U4 的应用验证需要不同的目标内容。输入缺失时报告到具体阶段，不把技术夹具作为实际内容验收。

第一轮不以组件数量作为进度。候选数量由参考中真正可复用的表达决定；同样不以生成一套抽象风格规则作为 U3 完成证据，必须存在可运行成员和连续演示。

## 9. 验证范围和完成边界

必做检查集中在这次变化：

- 目录与包引用：版本固定、依赖齐备、损坏可识别、重复导入不覆盖已有资产。
- 时间：语义事件绑定目标词，删词或时长不足有明确提示，原声和画面使用同一时间映射。
- 编辑保护：换风格、更新资产、保存重开和撤销后，用户参数与锁仍正确。
- 实际结果：参考关键状态、重建连续动画、换内容样片及最终视频分别查看；实际试听后才报告听感。
- 失败恢复：参考处理、编译或渲染失败时保留已保存阶段和上一可用结果；取消及重试不发布过期任务。
- 备份：新库、风格包和项目保存的版本能够配对恢复；同机恢复不冒充跨机器验证。

不恢复旧 194 项的批量验收，不把其他历史长测、全部画幅或任意动态资产收集带入本轮。首轮以当前 16:9 工作流为实际验收范围，其他画幅只有验证后才声明支持。

用户集中确认资产与风格效果，并沿用逐段成片确认；不为每个内部工具动作增加批准步骤。最终审美仍由用户决定。

## 10. 本轮不扩展的范围

- 不重建桌面 App、专业多轨剪辑器或内置 Agent。
- 不接入模型训练、自动爬取创作者全站或收费素材生成服务。
- 不承诺任意成片都能无损还原原工程、自动生成全部三维/实拍素材或自动识别所有隐藏图层。
- 不新增透明层导出。
- 不让参考视频里的操作说明成为工作台执行指令。
- 不在本次计划编写中清理组件、迁移工程、修改运行时代码或发布新功能版本。

执行入口：从 U0、U1 开始；具备首条参考后推进 U2，完成首个可用风格包后，用不同真实内容验证 U3、U4。所有后续变更在本文件对应阶段记录状态和实际证据，不再另起互相矛盾的完整计划。
