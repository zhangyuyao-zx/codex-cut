# Codex Cut 编辑体验与底层升级计划

日期：2026-10-22

状态：**A、B 阶段已实现并完成独立工程的技术验证；C—E 尚未开始**。B 的界面审美及用户实际使用接受待反馈，正式插件发布仍在 E 阶段。

基线：`v0.2.3`，提交 `9de13a2ea4072dfc6fb10e8946e14813fce7984b`。

## 1. 目标与范围

把目前主要靠侧栏参数操作的工作台，升级为可以直接点选、拖动、改字，并能和 Codex 接续工作的可视化视频编辑器。吸收 OpenFilm 的界面组织、直接操作、编辑命令、事件同步与资产封装设计，继续使用现有 Remotion 场景和制作链路。

产品职责保持明确：**Codex 理解内容、设计画面、写动画；工作台呈现和执行真实编辑；用户决定最终审美。** 可以给参考，也可以直接原创，不要求先选组件。最终交付仍是可以继续编辑、逐段审阅并合成的视频工程。

外部使用流程：导入素材 → 粗剪并检查 → 设计全片视觉段落 → 实现并审阅代表段落 → 逐段制作、修改、确认 → 合成和导出。内部沿用六步方法：**粗剪 → 视觉段落 → 视觉对象 → 视觉布局 → 包装设计 → 动画实现**。六步是创作方法，不增加六个页面或六道审批。

本轮不做：更换渲染引擎、恢复桌面 App、内置聊天 Agent 或模型供应商平台、云协作、透明层导出、专业剪辑软件全功能复刻、重建旧 194/700 项组件库。**DJI 视频不重剪、不重做，不改写原有确认。**

## 2. 现有成果如何处理

| 现有能力 | 本轮处理 | 需要补的部分 |
|---|---|---|
| 多素材粗剪、逐字稿、稳定词 ID、TimeMap、原声链路 | 复用 | 把现有操作接入统一编辑壳层与时间线 |
| 原创 Remotion 场景、声明式参数和可选中对象 | 复用 | 画布操作、真实图层、对象变换与就地改字 |
| 用户 overrides、锁、revision、原子保存、撤销 | 保留并扩展 | 操作级命令、并发冲突处理、拖动一次对应一次撤销 |
| 逐段指纹、局部渲染、精确样片确认与合成 | 保留 | 与新编辑操作正确联动，避免误用旧画面 |
| 全片共同样式、真实分镜对照 | 保留 | 放进一致的编辑与审阅交互，不再增加设计表 |
| 素材提需、段落反馈 | 保留 | 清楚定位到段落、对象和相应播放位置 |
| 参考提炼、视觉资产、风格包、我的动画和动画包 | 统一现有入口 | 看清效果、适配当前内容、保存与复用；不再新建平行库 |
| 工程备份与恢复 | 复用并补覆盖 | 核对代码、依赖、参数、时间和确认能否配套恢复 |

上述“复用”指当前工程已有对应实现，不表示任意场景都具备完整能力。尤其是：当前能点击声明对象、调参数，**尚不等于任意对象都可拖拽、旋转、直接改字或完整回滚源码**。

## 3. 最终界面与操作方式

仍保留「剪辑」「制作与审阅」两个工作区，使用同一套编辑外壳、播放器控制和选择规则。切换工作区改变操作内容，尽量保留当前播放位置与上下文。

| 位置 | 内容与交互 |
|---|---|
| 顶部 | 项目、保存状态、撤销/重做、工作区切换、导出；任务进度简洁显示 |
| 左侧 | 素材、段落/逐字稿、图层、我的资产；按当前工作区提供相关入口 |
| 中央 | 完整等比画面；点击选中、拖动位置、缩放、旋转，文字可双击编辑 |
| 右侧 | 当前所选对象的真实属性；只显示这个对象支持且有实际效果的控制 |
| 底部 | 视频片段、音轨/波形、段落与动画事件；定位、缩放及必要剪辑操作 |
| 审阅区 | 本段版本、修改意见、素材需求、确认本段/进入下一段；放在相关段落上下文中 |

左、右侧栏可收起与调宽，时间线高度可调。16:9 工程始终完整显示 16:9；空间不足时等比缩小或收起辅助区，不能拉伸、压扁或裁掉画布。其他比例按工程本身比例显示。

视觉采用克制的 macOS 风格：浅色中性编辑区、清晰层级、细边框、统一字号和间距；半透明玻璃主要用于顶栏、浮动工具与弹出层。视频、文字、属性值和时间刻度的清晰度优先。玻璃效果不覆盖画面内容，也不作为每块面板的装饰。

对话继续留在 Codex。工作台提供当前段落、对象、时间、版本与未保存状态，使“这个字大一点”“这里比口播晚了”能定位到实际内容。用户不需要填写动画协议或设计自评。

## 4. 吸收 OpenFilm 的底层设计

### 4.1 一个权威项目视图，共用一套编辑命令

在现有 cut、production、资源和选择存储上建立统一的项目快照读取层，带各自 revision 与依赖身份。读取期间如有变化，有限重读或明确提示刷新；不返回混合版本的快照。不为“统一”再造一份重复项目数据，也不把所有数据硬塞进一个巨型文件。

前端操作与 Codex 接口逐步共用经过验证的编辑命令及 reducer。命令以稳定的 `sceneId/objectId` 定位，包含操作 ID、目标版本、变更字段和真实 actor；重复提交不重复生效。先覆盖实际需要的位置、尺寸、旋转、文字和参数操作，再接现有剪辑与图层操作，不预建通用工作流平台。

拖动时只更新本地交互状态，松手后合并为一次持久化和一次撤销。前后端使用相同的约束与计算规则。写入基于最新版本：不冲突的字段可重放；同字段被改、对象被删或被锁时明确处理，不能静默覆盖。撤销逆转本次操作涉及的字段，不通过恢复整份旧 JSON 抹掉 Codex 或用户后来的其他编辑。

### 4.2 作者实现、用户调整和派生结果分开

保留场景代码、内容参数和口播事件；把用户的对象调整、覆盖和锁独立保存。新增稳定对象 ID、父子关系、类型、编辑能力和必要的变换/文字映射，不依赖数组下标或容易变化的 DOM 路径。

普通 DOM/SVG 场景先支持文字、图片、视频和对象组。位置、缩放、旋转采用明确的对象变换层，和动画自身的逐帧变换正确组合；预览和导出使用同一套计算。画布改字必须落到对应参数或明确的文字字段，不能只改临时 DOM。

**不承诺任意代码自动变成完整图层编辑器。** Canvas/WebGL/Three 内部对象需要作者提供编辑入口；没有入口时可编辑明确的整体对象或由 Codex 适配。未支持的控制不显示假按钮，不把一张渲染图伪装成可分层对象。旧场景继续播放，按实际使用逐个适配，不开启全库重做。

### 4.3 内容变化、播放状态和任务进度分开同步

项目变化和任务进度改为可订阅事件，支持断线后重新读取权威快照。源码和静态依赖变化只通知受影响内容。逐步替换现有固定轮询；切换前保留必要降级读取，避免同时存在多套写入者。

播放头、选择框、渲染百分比和面板开合属于运行状态，不进入场景内容身份，也不能因此重建播放器输入、重启媒体时钟或清空草稿。后台任务晚完成不能抢回页面、替换新内容或自动制造用户确认。

### 4.4 确定性时间、连续播放与精确取帧分别处理

继续沿用稳定词 ID 与源时间/成片时间/段内时间映射，Remotion 动画继续按帧计算。补齐资源就绪与错误边界：同一份输入在同一帧应得到同一画面，随机跳转不依赖前一帧是否播放过。

连续播放优先复用媒体解码、代理与预加载；暂停定位和渲染走精确帧。只对实际较重的段落增加后台视频预览缓存，缓存与交互图层明确区分。编辑后立即使受影响缓存失效，保留上一成功结果但清楚标记其版本。

渲染任务先检查当前 Remotion 的浏览器复用、并发、取消能力，再决定需要补的调度。不能先自建第二套渲染服务。继续使用现有较细的场景与依赖指纹，不能退化为“改一处，全片全部失效”。

### 4.5 资产、版本与恢复围绕真实依赖

沿用现有保存动画、动画包、视觉资产和备份协议，补齐被保存对象/组/场景的代码、静态依赖、素材槽、参数、口播事件及预览。保存时选择少量有用的编辑参数；使用时替换目标内容、素材和词锚点，不强迫用户手填底层映射。

实际代码与必要依赖必须能随版本或包恢复。临时缓存可以再生成，已确认输出、确认凭据和需要恢复的作者源码不能混入缓存清理。固定资源版本与旧项目兼容规则继续保留。

## 5. 开发顺序与每阶段交付

下面 A—E 是本次工程实施顺序，与六步创作方法是两件事。每阶段都有可操作结果，不以新增文档、接口数量或目录数量作为完成标准。

### A. 先做通一段真实编辑

**交付：** 在独立工程的一段现有 Remotion 场景中，完成选中对象 → 拖动/缩放 → 改字 → 保存 → 撤销/重做 → 重开。同步落下最小的快照、编辑命令、对象覆盖和事件通知；不先大改整套界面。

**实现范围：** 场景对象描述、对象预览、属性面板、production 保存与命令接口。扩展现有 overrides/locks 的兼容结构，旧工程缺少新字段时按原行为读取。

**通过标准：** 用户把对象放大并改字后，Codex 修改另一对象或动画，用户调整仍保留；重开与实际渲染一致。一次拖动只占一步撤销；锁、同字段冲突和目标删除均有明确结果。技术验证使用独立工程，不写入用户影片确认。

这是第一份真正交付。若这条链路没有做稳，不扩大到完整时间线或资产改造。

### B. 做成完整、好用的编辑界面

**交付：** 新编辑外壳、可调面板、完整预览、画布选择与手柄、图层和上下文属性；覆盖「剪辑」「制作与审阅」。以标题、数字、流程三种内容检验布局，不只美化单张截图。

**实现范围：** 整合现有 `Roughcut`、`Production`、`ObjectPreview`、`ObjectProperties`。图层先提供选择、锁定、显示/隐藏和有效的层级调整；同一父组内排序与改变父子关系分开，无法支持的结构不提供误导操作。必要快捷键、右键菜单和输入焦点规则随真实编辑接入。

**通过标准：** 点击画面、图层和右侧属性指向同一对象；缩放后的指针与手柄准确；双击文字能编辑，输入时不误触播放/删除快捷键。窄窗口、切换工作区、暂停和重新定位均不拉伸画面、不因界面刷新制造黑屏或清空草稿。

此阶段给用户看可操作版本，确认视觉方向和操作感受。工程实现通过与用户审美接受分别记录。

### C. 把时间线与素材操作接进同一闭环

**交付：** 真实片段、波形、段落和动画事件时间线；素材、图层、逐字稿与资产入口指向当前画面。常用剪切、修边、排序、吸附、音量等优先复用现有能力，不扩展专业剪辑软件的全部功能。

**实现范围：** 现有剪辑接口、TimeMap、事件绑定、素材提需、资源页与动画存档。拖动动画事件修改其偏移或时长并保留语义锚点；缺失锚点明确待重绑。资产先看效果再应用：有原样片就可播放，需要目标素材则说明并绑定，不用空黑框冒充预览。

保存对象/组/场景复用接在现有资产协议上；明确支持范围和缺少依赖。全片共同风格、关键帧对照、反馈和逐段确认放到一致的编辑上下文里，不新增第二套制作流程。

**通过标准：** 删除前面一句后，后面动画按词重新定位；被删词的引用有提示；无关段落的有效确认不被无谓清空。保存一项效果并换内容/素材使用后，仍能编辑，原工程不被改写。素材缺失只阻止相关段落，用户仍能处理其他段。

### D. 收敛预览、同步与渲染性能

**交付：** 事件同步替换相关轮询，精确定位与连续播放各走合适通路；资源就绪、重场景缓存、任务取消与过期输出处理一致。

**实现范围：** 现有 Player 输入、依赖跟踪、局部指纹、预览缓存和 Remotion 渲染路由。对改变的普通场景和重场景做实际测量：操作反馈、跳转、切段与音画连续性；按结果决定缓存和预加载，不先定未经测量的全局优化。

**通过标准：** 同一段在不同随机跳转顺序下，关键帧结果一致；缺字体、缺素材、文本溢出或运行错误能定位。连续播放不因进度/选择事件重建时钟，段落边界无程序产生的重复口播或黑场；取消与旧任务晚完成不能覆盖新结果。

程序检查可发现技术缺陷，不能代替语义重复检查、风格判断或审美验收。无需为此重做 DJI；使用独立技术工程及本轮实际改变的场景验证。

### E. 完成恢复、兼容和发布

**交付：** 新编辑状态与代码能配套保存、命名版本与恢复；资产包依赖完整；旧工程可继续打开；插件/API/Skill 文档和截图与实际产品一致。

**实现范围：** 扩展已有备份、恢复和动画包，核对源码、用户覆盖、锁、词绑定、固定风格版本及媒体引用。新数据写入先在独立副本验证，保留 v0.2.3 与迁移前副本；不把“只恢复 JSON”称为完整源码回退。

**通过标准：** 在独立工程完成手动编辑 → Codex 接续修改 → 重开 → 原声样片 → 明确技术性段落确认 → 合成导出的闭环；恢复副本能够复现对应版本，原文件与原确认保持不变。技术工程确认只用于校验机制，不是用户对实际作品的认可。

按实际改动运行受影响检查和最小有效实机验收。完成后更新 README、状态、插件说明和第三方声明，提交并推送 GitHub；发布产品版本时再同步版本号、插件产物、标签和 Release。计划文档本身不升级产品版本。

## 6. 代码职责与迁移方式

| 责任 | 主要落点 | 约束 |
|---|---|---|
| 快照、命令、冲突与操作级撤销 | 在 `workbench-local` 的共享编辑核心中补充；具体新文件在 A 阶段确定 | 前后端共用纯计算和验证，不另建重复项目库 |
| 对象身份、能力、变换与文字映射 | 现有场景协议、`ObjectPreview`、`ObjectProperties`、场景渲染公共层 | 预览/导出一致，覆盖和锁不能被代码改动绕过 |
| 编辑外壳、图层和时间线 | 当前主入口、`Roughcut`、`Production` 与相关组件 | 不新增独立编辑器应用，不恢复内置聊天 |
| 同步、缓存、渲染与依赖 | 现有项目路由、依赖跟踪和渲染任务 | 内容身份与播放/任务状态分离，旧输出不得替换新版本 |
| 资源与版本 | 现有视觉库、动画存档/包、恢复模块 | 一套资产入口，固定版本、真实依赖和兼容读取 |
| Codex 接续操作 | 现有插件工具与制作 Skill | 真实 actor、revision、草稿和用户确认边界保持有效 |

采用增量替换：先新增共享核心并接一条实际编辑链路，再迁移对应界面和接口。旧读取/项目兼容保留到新链路通过，旧写入最终收口到同一命令执行，不长期维持两套不同规则。外部素材不覆盖，机器配置、用户工程和私人媒体不进入 Git。

## 7. 验收与执行纪律

最小验收覆盖五类风险：

1. **编辑准确：** 画面、图层、属性、撤销与导出使用同一对象和同一逻辑坐标。
2. **调整不丢：** 用户与 Codex 交替改动，锁、草稿、并发冲突及重开都保留正确结果。
3. **时间正确：** 删句、重排和跳转后口播与动画仍一致，失效引用明确暴露。
4. **版本可信：** 依赖变化只影响相关结果，确认绑定真实输出，恢复覆盖必要代码和资产。
5. **实际好用：** 用户能在完整画面上完成操作，且不会被技术字段、空预览和后台任务干扰。

主代理负责需求、架构、集成与最终产品/视觉判断。需要并行时，只把边界清楚的编码交给 `sol_worker`，独立只读检查交给 `luna_runner`，已定规格的机械工作交给 `luna_worker`；遵守最多两个子代理且最多一个写代理。小任务和紧密依赖步骤本地完成，不为并行而拆分。

阶段内修复本次变更造成的问题；新的独立设想记为后续候选，不自动加入这轮范围。检查围绕改变和实际风险，已通过且未受影响的检查不反复重跑。代码完成、实际验证、用户接受分别报告，不能相互替代。
