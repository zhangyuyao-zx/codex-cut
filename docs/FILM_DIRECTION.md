# 全片风格与分镜 · v0.2.2

本轮处理两个制作缺口：共同风格没有持续落到新增场景；逐段制作缺少全片实际画面对照。六步内容方法、逐段原声审阅、用户确认和最终合成保持原流程。

## 共同样式实际生效

选择固定版本风格包后，场景声明 `styleBindings:{参数名:token名}`，代码实际读取对应参数。该机制支持字体、字号层级、线条、圆角、间距、动作时长与缓动，也支持原来的配色。原创场景无需加入包成员才能继承共同 token；成员专用预设仍按固定版本作用。

优先级：**全片共同默认值 → 段落显式参数 → 用户 overrides**。新建段落、预览、渲染和参数检查共用同一解析结果；读取工程不隐式改写保存文件。参数变化进入渲染身份，旧样片不会当作新效果。

包装页的「样式映射」显示适配范围；选中段落后可看到不同字段的实际值、共同值、来源和锁。用户点「未锁定样式跟随全片」，只清除有绑定的未锁定样式覆盖；内容、非样式几何参数和锁保留。Codex 调同一入口时保留所有用户覆盖。撤销沿用现有方案版本。

没有声明映射、缺 token、非法值或仅写了映射却没在代码使用时，仍需要 Codex 适配。程序可以验证参数和身份，不能证明代码视觉上执行了设计意图，更不能判定审美通过。

## 全片一起看

进入「包装与审阅」，展开「全片分镜」，点击「更新关键帧」。只从已有成功样片提取，每段最多三张 640×360 图片，不重新渲染视频。优先选择语义动作完成附近与段落后段；没有动作信息时按区间取样。默认显示后段画面，可切换前中后三帧、点击放大、跳到对应帧编辑。

卡片包含表达任务、共同样式适配、观察及相似设计提醒。当前样片与历史画面明确区分；尚无样片则显示待制作，抽帧不冒充画面生成。总览默认收起，展开后只在样片身份变化时重读，不跟着每一帧播放轮询。

相似提示比较设计中的对象角色、布局与动作关系，不比较组件名称或标题文案。相同描述只提示复查；有意复用可以保留。Codex 需实际检查不同表达是否被同一个构图掩盖、连续段落是否混杂，并通过播放确认动作节奏。程序不设构图配额，不自动发明另一种排版。

## 观察与用户确认分开

看完真实画面后，可记录风格一致性、构图差异或有意复用、具体说明，以及实际对照过的相邻画面。记录绑定 scene key、render ID、视频内容哈希与关键帧 ID。自身或对照来源变化后，旧观察自动成为历史记录，不会继续显示为当前结论。

图片与观察位于工程的 `production/storyboard/`，与原有确认账本分开。保存观察不会批准段落、设置资产 ready 或启动合成。静态关键帧不证明完整运动或音画同步；没有视觉能力时不得填入未实际观察的视觉判断。

本地文件经过真实路径边界和来源校验；帧以内容身份缓存，视频哈希以文件身份、大小及修改/变更时间复用。更新关键帧失败不会发布半份索引。抽帧是可重建产物，观察记录是工程数据，备份时保留整个工程。

## 插件入口

- `read_project {section:"storyboard"}`：读取全片画面与观察。
- `update_project {operation:"production/storyboard",expectedRevision,data:{}}`：提取已有样片关键帧。
- `production/visual-review`：记录实际观察，必须引用真实当前帧。
- `production/follow-style`：当前段跟随共同样式，保持用户修改保护。

详细 body 与身份限制见 [操作协议](../workbench-local/plugin-package/codex-cut/skills/video-workbench/references/operations.md)。插件新版本需宿主新任务加载，不能把脚本读取成功说成旧任务工具已热更新。

## 本轮边界与证据

采用独立合成素材验证标题、数字、流程三种不同构图，共享同一套样式。改变共同 token 后核对实际参数和真实渲染，检查用户覆盖/锁、关键帧定位、观察过期及确认隔离。相关单元检查、插件合同与 TypeScript 检查按变更范围执行。

DJI 的粗剪、制作方案、已有样片和确认没有重做。此次工程修复不会追溯美化旧成片；后续制作采用新继承与实际对照流程，具体审美仍由用户把控。
