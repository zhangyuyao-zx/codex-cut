# 实时预览重复口播：播放时钟修复

用户提供的新录屏确认了实时预览中的重复播放问题。当前修复只涉及浏览器预览，不修改粗剪区间、场景设计、已生成视频或用户确认记录。

## 原因

制作页通过 `frameupdate` 更新播放位置，每次更新都会重新创建场景对象。两个预览入口又在每次 React 渲染时创建新的 Player `inputProps`。在已安装的 Remotion 4.0.489 中，输入对象身份变化会重建 composition metadata 和 video config；播放时钟的 effect 依赖 config，因而不断重新计算计时起点，丢失帧间累计时间。

音视频标签依然以 1 倍速运行，逐渐领先于变慢的动画时钟。Remotion 的媒体同步检测到时间偏差后执行 seek，把媒体拉回动画时间。半秒左右的声音因此重复播放。此处没有第二条正在播放同一内容的音轨，也没有重复添加剪辑区间。

另一个相关隐患是预览的定位 effect 依赖时间回调引用；调用者更换回调时也可能触发暂停和重新定位。

## 修正

- `SceneModulePreview` 按 JSON 内容保留场景与转场快照，缓存带已加载图层的完整 Player 输入。进度更新和相同内容的接口轮询不重建 composition config；真实参数、媒体、模块和图层变化仍会更新预览。
- `LegacyProgramPreview` 同样保留内容未变的 Player 输入。
- 两个入口通过 ref 读取最新时间回调，回调引用变化不再触发暂停和定位。切段、显式定位、加载新模块或时长变化的原有行为保留。
- 未增大音画容差，未关闭媒体同步，未修改 Remotion 安装文件。

## 实际证据与验证边界

父代理在用户当前工作台复现：连续约 6 秒采样中有 3 次声音回退，分别为 `1.963 → 1.417`、`3.240 → 2.751`、`4.759 → 4.233` 秒。界面段落时间只推进约 4 秒；视频同时回退。录屏约 11 秒的播放过程也只推进约 6.8 秒段落时间。

修正后同一工作台、同一段落、同一媒体以约 120 毫秒间隔采样：6.122 秒内音频从 0.426 推进到 6.542 秒，视频从 0.457 推进到 6.577 秒，均无倒退；页面时间同步推进。期间覆盖了正常接口轮询。TypeScript 检查通过。

这里验证的是实际播放器的时间行为，并非模型试听结论；不据此声明此前所有成片的粗剪内容已经验收。没有重新渲染用户影片，也没有写入任何样片认可。

本机录屏、抽帧、转写及工程哈希证据存放在忽略的 `projects/repetition-recording-20261021/`，不发布私人素材。旧的“尚未复现”记录由本次证据补充，不能继续用转写文本没有重复来否定播放器的实际重复。
