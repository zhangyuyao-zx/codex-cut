## 界面与交互

- 「剪辑」「制作与审阅」继续使用同一个顶部入口、面板开关及编辑外壳。替换原玻璃面板布局样式，保留视频内容自己的样式。
- 左侧制作区切换段落/图层；右侧切换当前对象属性、段落审阅和素材需求。隐藏面板及切换侧栏不卸载其输入状态，草稿仍保护跨工作区导航。
- 面板宽度与段落区高度可拖动或用键盘调整，外观偏好不写进项目修订。进入窄窗口时收起侧栏，通过顶部按钮以抽屉打开。
- `FittedCanvas` 按剩余实际宽高等比适配 16:9，不通过固定高度或拉伸挤压画面。段落区变化时重新适配，渲染输入不因面板调整改变。
- 画布、图层与属性使用同一 selectedObject。图层直接选择、隐藏、锁定和菜单排序；右键画面也能进入对应操作。旧对象没有声明能力时不显示假的隐藏或排序控件。
- 空格播放/暂停，左右方向键逐帧，⌘/Ctrl Z 撤销、Shift ⌘/Ctrl Z 重做。输入框、文字输入组合、菜单、树节点和分隔线不触发画布快捷键。菜单在切段或离开焦点时关闭。
- 底部提供真实段落定位及原有分镜入口；完整多轨时间线仍属于 C，没有把这条段落导航称为已完成的剪辑时间线。

## 真实图层合同

在 A 的可选能力上增量扩展：

```json
{
  "id":"second","label":"第二步","kind":"text","parentId":"flow",
  "parameters":["second"],
  "canvas":{"transform":true,"text":"second","visibility":true,"reorder":true}
}
```

kind 为 text/image/video/shape/group。parentId 是作者固定的对象关系，校验未知父级、自引用和循环；本阶段不做换父级或自动 DOM 重组。默认旧 manifest 与旧工程继续读取。

`EditableCanvasObject` 的 parentId 必须与清单一致，父组使用真实固定的嵌套定位。用户位移、缩放与旋转仍在作者帧动画外层；嵌套子对象的拖动坐标及选择框会计入已声明父组的用户缩放/旋转。未适配的任意父级动画坐标、Canvas/WebGL 内部像素仍不能自动成为独立图层。

新增状态：

```json
{
  "objectVisibility":{"orb":false},
  "objectOrder":{"root":["headline","note","orb"],"group:flow":["first","second","third"]}
}
```

visibility 缺项按 true；order 缺项保留作者顺序。顺序数组从后向前，必须是完整同级排列，同级全部声明 reorder 才可调整；不能借排序跨组。只有存在覆盖时包装节点才用 zIndex 执行顺序，隐藏使用实际 display:none。这些值经过共享绑定进入 `SceneModuleSurface` 的 provider，预览、正式渲染及快照读取一致。

增加两种共享命令：`visibility` 的 key 为 visible、before/after 为布尔；`layerOrder` 的 key 为 siblings、before/after 为同级 ID 数组。沿用 A 的原子日志、幂等回执、字段冲突与精确撤销，不恢复整个旧方案。逆转一个组不更改其他组及用户参数。

父组锁保护子对象，Codex 不能通过直接写入、排序或撤销自己旧操作绕过后来的锁。排序涉及的同级锁也要检查。API 自身补齐 Codex 草稿守卫，不能仅依赖插件桥接的前置检查；用户未保存时拒绝 Codex 命令，revision 不变。

```sh
npx tsx scripts/prepare-editor-demo.ts projects/editor-stage-b-demo --stage-b
WORKBENCH_PROJECT_DIR=projects/editor-stage-b-demo WORKBENCH_PORT=4343 npm run dev
```

本轮证据在 Git 忽略的 `projects/editor-stage-b-demo-20261022/`：
