# Dots 采用标准与执行入口收口

新工程已采用材料与代表样片先行的 schema 2，但旧目录、命令帮助及生成说明仍能把作者带回全片动作脚本；实际观察也可能只谈解释含义而遗漏美术。此次统一入口及适用标准，不增加新的生产账本或用户审批。

## 当前职责

- `tools/dots-production/WORKFLOW.md`：唯一新制作流程。
- `studio/standards.json`：唯一完整采用标准，包含13条导演学习、9项美术设计、15项后续决定。`studio standards/resume`读取它；`CRAFT.md`只索引部件与实例。
- 原生 `production.json`、词锚点、场景源码：实现依据。
- `authoring.json`：选材、参考、代表关系、实际观察；`capture`输出实际视频、帧、参考、空白观察及适用对照问题。
- `tools/reference-study`：独立研究能力，不作为每期制作前置。

## 执行行为

`findings[].topics`与`referenceComparisons[].topics`在原有观察中记录实际覆盖。一个有证据的发现可涉及多项，不另建质量表。代表样片需要实际比较构图、字块、框内物件与动态，真实素材另检查对应关系与融合；全片检查理解推进、构图、节奏和接点。缺项会阻止把该观察当作已完成校准而扩展。技术检查不能判断描述真假或审美，也不生成作者观察。

既有schema 2观察若缺新版提示，可对同一渲染重新capture并实际补查；观察措辞和题目覆盖不进入画面hash，不强制重新渲染。schema 1作品继续按保存协议兼容，不迁移已完成影片。

`prepare/init/init-film/bind-native`等历史创建命令只在显式`legacy`命名空间运行。`bind-native`也拒绝覆盖空的schema 2记录，避免使用底层接口降级。旧只读诊断和冻结的1.0—1.3源码保留；它们不是新流程的另一种默认选择。

`capture`返回实际`media`和`chatMarkdown`，用于对话内的真实视频与关键帧交付。本机路径不被声明为公网链接；实际播放与作者观察、用户认可分别处理。

## 验证范围

- TypeScript通过；方向及原生门禁17项、CLI/绑定7项通过。
- 旧固定源码与CLI兼容32项、原参考包与审片身份9项通过。
- 插件桥接25项通过；1项会尝试过期写入的生产环境检查按默认跳过。
- Skill格式及固定1.3.0源码21个文件哈希通过。
- 使用本机既有17.1秒隔离样片实际执行capture，产生三个指定时间帧、参考视频、七类对照问题和空白观察。没有重渲染已验收影片，也没有把技术样片判为审美通过。

本机技能源和安装缓存已同步，运行服务实际升级到能力2；当前已完成的schema 1工程继续显示`legacy-v1`且检查有效。媒体、混音、原生分镜及确认记录的保全核对留本机，不提交私人素材或路径。公开源码更新与具体影片验收相互独立。
