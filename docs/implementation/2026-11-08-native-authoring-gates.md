# Dots 制作入口约束

## 问题与结果

参考准备、动作脚本、全片编排和审片工具已存在，但原生渲染/确认/合成没有要求使用它们。因此“已读方法、已执行 prepare”可以与占位设计、未对照样片同时存在。插件安装源还可能落后于仓库，源码更新也不代表运行服务已经加载。

本次把既有制作要求接到原生入口，继续区分技术记录完整、作者实际判断、用户确认。视觉源码版本保持 1.3.0，新增入口协议 1；不更改既有固定发行内容。

## 实现

- 本机忽略 Git 的策略设置默认适用范围，新工程自动生成空制作绑定。旧工程不迁移，已选其他方向按已有依据处理。
- 渲染前检查全片设计、逐段真实词时间、所选真实参考区间及实际代码依赖。样片记录渲染当时的设计身份；过程中改变设计不发布为当前结果。
- 确认前检查当前视频/参考/规格/播放副本/实际帧与观察身份、完整原速观察、目标尺寸、对象/构图/字级/动作/节奏/交接六类观察和静止窗口处理。返修结论不能用于确认。
- 合成前比较当前采用的相邻和同类样片；合成后完整回看和听辨当前混音，才能标为最终自检完成。下载预览仍可用于检查。
- 过期审片与设计在状态页、具体确认、合成和整片确认处同步失效；历史文件与历史确认不删除。
- 工程绑定固定套件版本；目录的 future currentVersion 不会直接替换本期版本。
- 插件 summary、整片及单段读取均暴露三阶段 authoring 状态；单段读取使用原生局部检查，避免把未实现的后续段落误作本段缺项。服务健康信息报告入口协议版本，便于区分源码/安装/运行状态。

使用与记录格式以 [NATIVE_AUTHORING.md](../../tools/dots-production/NATIVE_AUTHORING.md) 为唯一说明。

## 验证与边界

针对本次变更运行类型检查、设计/审片/合成身份和失败路径、原生 API 拦截、新建工程、绑定工具、原有段落确认与混音、插件协议的检查。夹具不用于声称实际美术验收。实际工作台另核对健康版本、待自检状态和工程身份，没有触发当前项目的新渲染或写入确认。

流程约束只能拒绝缺项、过期身份和明显不完整记录。它无法证明作者确实仔细看过、观察是否正确，也无法给画面精致度打分；真实素材的准确性、框内细节、动作的解释作用和整体审美仍由实际对照负责。任意本地脚本输出可作为草稿，不能伪称当前原生流程已完成。

本机策略、内容工程、媒体、参考原片、语音与观察记录均不进入公开仓库。安装插件时保留本机连接配置；运行服务无任务、无草稿时再重启。回退时保留工程和媒体，按提交范围恢复入口代码及相应本机策略，记录原因，不覆盖活动制作文件。
