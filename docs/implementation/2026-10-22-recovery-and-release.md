# 0.3.0：配套恢复、兼容与交付

2026-10-22。对应 [OpenFilm 编辑升级计划](../plans/2026-10-22-openfilm-editor-upgrade.md) E 阶段。

## 本轮结果

A—E 核心实现与隔离工程技术验证完成。产品保留现有 Remotion、六步创作方法和逐段用户确认；没有重做 DJI，没有扩展内置 Agent 或第二套渲染平台。用户实际使用和审美接受仍待反馈。

备份使用已有 checkpoint 链路，增加名称、捕获代码版本、剪辑/制作 revision 和代码/工程/配对 SHA-256。信息从暂存的已捕获文件与排序清单生成；名字和时间不进入内容身份。校验核对实际字节、模式、来源修订与内容身份。旧 schema 1 无新字段备份仍可校验和恢复。

恢复始终写到新目录，实际包含对应工作台代码与工程。对象覆盖、锁、变换、图层、事件节奏和编辑命令日志与剪辑词/媒体、动画存档、固定视觉库一起保留。界面将技术标识收进“版本详情”。CLI、HTTP 和插件使用同一链路，不接受浏览器传入的任意目标路径。

插件仍为七个工具，`read_project` 增加 checkpoints，`update_project` 增加 checkpoints/create、verify、restore。备份操作使用当前制作修订并保留草稿/任务守卫；恢复不切换活动项目。A—D 已增加的对象命令、剪辑分割、事件调节和动画存档合同随本次插件发布一起安装。

并行本地服务还暴露了 Vite 在 `hmr:false` 时仍打开默认 WebSocket 端口的现象；补上 `ws:false`，保留已有服务事件和模块失效处理，不再争抢 24678。

- 主代理：桥接 **20 项**通过；集成后类型检查与 diff 格式检查通过。未重跑 A—D 未受影响的整套测试。
- Luna Runner：只读核对实际持久化路径，未发现 A—D 编辑数据或必需素材遗漏。根脚本/演示资产及本机插件路径边界已补入恢复说明。
- 实际工程：`projects/editor-stage-e-demo-20261022/`，只有合成提示音、生成画面与合成词锚点。

实际在 UI 改标题、放大到 1.15 倍并锁定标题，再以 Codex 命令修改另一对象的文字。重开后标题、大小和锁保留。三段各导出 4 秒/120 帧/1920×1080 H.264/AAC 样片。技术确认仅在该独立工程写入，并有 `TECHNICAL_CONFIRMATIONS.json` 明示用途；不是用户影片认可。合成实际得到 **12 秒、360 帧、一条音轨**。

通过 UI 创建“E 技术验证 · 手动调整保留”，465 个文件/约 88.3 MiB，来源为代码 0.3.0、剪辑 r2、制作 r5。UI 恢复到新的 code/project 配对目录；用独立 npm 缓存执行 `npm ci` 安装 331 个包，并从恢复代码启动 4346，使用本机既有浏览器/合成器。三段指纹、技术确认和 assemblyReady 保持一致，programError 为空。

从恢复副本重新渲染标题段，**120 帧解码后逐帧校验一致，解码音频 SHA-256 一致，段落 key 相同**。这验证实际源码、状态和素材一起恢复，不只是 JSON 读取成功。另实际导出并读取 `.cutanimation`：两项源文件，手动标题/参数与 1.15 倍图层变换保留，外部运行时要求明确。

原声是合成提示音，不据此宣称真人口播语义、所有声音条件或用户审美通过。恢复仍使用本机已有外部渲染器，不代表跨机器恢复已经验收。

## 范围与恢复方式

[恢复说明](../../workbench-local/RECOVERY.md)给出操作入口及从恢复 code 启动、绑定同份 project 的步骤。根 scripts/assets/docs 不属于当前工程快照；README 演示重建需相应 Git 仓库版本。本机运行依赖、字体和插件 local-config 也不能冒充跨机器已安装；恢复插件路径需重新指向对应代码。

保存动画仍以整段为单位，明确声明的 DOM/SVG 对象可直接编辑，未声明的 Canvas/Three 内部对象需作者适配。带新库 OBJECT 的嵌套动画包及风格包独立分发不在本轮支持内；拒绝缺依赖的伪成功包，不以通用打包平台扩大范围。

技术证据、版本归档和媒体留在 Git 忽略的测试工程 verification；公开截图只含合成图形和通用文字。正式影片内容质量、风格与长期编辑体验继续由实际使用判断。
